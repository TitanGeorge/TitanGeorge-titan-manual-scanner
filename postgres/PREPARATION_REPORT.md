4. **Fresh initialization.** `node admin.js init SCAN_ID root.json` creates a paused scan, root state and page-1 job atomically. The scan starts with zero files/bytes. It never erases existing scans or the shared source-identity table. Same-root active scans are prevented by an advisory-lock check and partial unique index. Intentional overlap requires explicit `allowParallel:true` through the initializer API.

5. **Persistent pause / kill switch.** `node admin.js pause SCAN_ID` persists disable/pause in PostgreSQL. Claims and page commits serialize with pause. Already requested metadata may commit safely; further claims are stopped. Paused state survives new processes/restarts. `validate-one` enables just one additional successful page and pauses atomically on commit. Ordinary app startup cannot start a worker; `run-worker.js` is a separate guarded explicit command.

6. **Worker flow.** Dedicated Client → claim transaction → lease/owner/token/attempt assigned → retained folder loaded → persistent pause rechecked → authenticated metadata-only page callback → atomic page processing → success returned only after commit. Runtime transport retains member login, igd.nonce acquisition, `igd_get_files`, shortcode 7, nested browser-compatible POST encoding and pagination. Source credentials are read only upon an eligible job, never during migrations/init/health/status.

7. **Transaction boundaries.** Claim and page processing are separate transactions. HTTP is outside transactions. One page transaction includes unique file upserts, snapshots, relationships, child folder objects/jobs, next-page job, folder/job status, fingerprint and scan progress/validation-pause update. Any error rolls all page effects back. A final lease-expiry check precedes commit.

8. **Deduplication.** File identity is `(account_id, drive_file_id)` with shortcut target identity. Relationship primary key is `(scan_id, folder_id, file_id)`, preserving references from multiple folders. Per-scan snapshots preserve historical filename/size observations across legitimate changes in later scans. A later known size fills a missing size; conflicting known sizes within one scan roll back the page.

9. **Pagination.** Job page and folder next_page are persistent. The returned next page is validated and queued inside the same committed transaction. Cycles/repeated pages are rejected. Completed folders cannot be automatically reclaimed/recrawled.

10. **Crash/restart.** SIGKILL inside an actual page transaction leaves no partially persisted files/pagination. After lease expiry another process can retry. A child process that commits/exits leaves durable state; a completely new process resumes the next page. Filesystem checkpoints and memory maps are not used by the fresh path.

11. **Leases/fencing.** Database clock controls expiration. Each claim increments fencing token. Owner/token/folder/page are checked under row locks; heartbeat uses the same fence. Stale workers cannot commit or fail a replacement lease. Expired-worker attempts eventually reach the terminal ceiling rather than retry forever. Default runtime lease is 600 seconds.

12. **Rate/retry controls.** Persistent defaults: concurrency one, one-second minimum page-claim spacing, five attempts. Concurrency is bounded 1–4 and configuration values are constrained. Actual transport calls also wait at least one second including authentication, have timeouts, and allow only known auth/metadata URLs. Retryable HTTP 408/429/5xx and transient failures back off exponentially from five seconds, capped at an hour; terminal page/data failures are blocked. Only sanitized fixed error codes enter PostgreSQL. A failed folder does not discard other committed inventory. No broad completed-folder retry command exists.

Database unavailability yields 503. `/health` verifies database and scan existence. Both are read-only and never invoke source transport. They were not registered on production.
