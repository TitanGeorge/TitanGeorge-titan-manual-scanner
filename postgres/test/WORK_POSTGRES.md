# Actual PostgreSQL test environment

Tests were run against Ubuntu PostgreSQL 16.15 binaries, TCP loopback port 55439, and a disposable cluster. The binaries and SQL/transaction engine were unmodified. All inventory responses were synthetic; the authenticated transcript test replaces `fetch` with a fixture implementation.

The Work namespace maps only UID/GID 0 (`/proc/self/uid_map` and `gid_map`: `0 0 1`). Ordinary non-root startup is unavailable. The **test-only** LD_PRELOAD shim in `work-test-uid.c` makes getuid/geteuid and ownership checks for `/tmp/titan-pgdata*` appear as UID 1, allowing initdb/server startup in this namespace. Unix-domain sockets are disabled; the server binds loopback only, and trust authentication is used exclusively for disposable test data. This does not emulate PostgreSQL queries or concurrency. Do not deploy this shim, use it on a regular host, or use this trust configuration with real catalog data.

The binaries were obtained by downloading/extracting Ubuntu `postgresql-16`, `postgresql-client-16`, `libllvm17t64` and `libpq5` packages into `/tmp/titan-pgbin`; no cloud resource was created. On this Work environment, run `bash test/run-work-postgres.sh` from `postgres/` after `npm ci`. Override `TITAN_TEST_PG_BIN_DIR`/`TITAN_TEST_PG_LIB_DIR` if extracted binaries are elsewhere. The runner builds the shim, creates a unique disposable cluster, runs the full suite, then stops/removes its own cluster.

On an ordinary host run a standard PostgreSQL server as a regular PostgreSQL user, **without the shim**, and supply `TITAN_TEST_DATABASE_URL` pointing to a disposable loopback database whose test role may create/drop isolated schemas. Run `npm test` from `postgres/`. The real suite refuses non-loopback database URLs. Without this variable the real tests are explicitly skipped, not reported as passed.

The crash test holds the page transaction using a PostgreSQL trigger, observes its backend in `pg_stat_activity`, sends SIGKILL to the actual Node worker process, then verifies rollback and lease-based recovery by a new process. PostgreSQL may finish the injected sleep before noticing disconnect; this explains the approximately 30-second test duration. A separate child commits and exits; another process resumes stored pagination. HTTP status/startup/restart tests run only on a newly spawned local application at port 55440. No Render or Service Alliance endpoints are used.
